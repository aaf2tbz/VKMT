The diagnostic `test/browser/boringssl-tls-client-probe.c` was updated to
split writes, drain multiple SSL_read results, and optionally enable CA
verification when a CA path is supplied. It compiled successfully against
the pinned Chromium-109 BoringSSL static libraries with LLVM-MinGW.

It is not counted as a trust gate: the current x86_64 BoringSSL process hits
the known custom-FEX `EXCEPTION_ILLEGAL_INSTRUCTION` (`0xc000001d`) in the
xtajit64 startup boundary before application output. The authoritative TLS
fragmentation proof therefore uses the all-architecture WinHTTP/WinINet
`valid-fragmented` lanes and the local CONNECT proxy, whose receipt is in
`capability.tsv`.
